# Chess & Cards 运维手册：发布与热更新

**适用环境**：1Panel + Docker Compose（默认目录 `/opt/1panel/apps/chess-and-cards`）  
**关联文档**：[1panel-deploy.md](./1panel-deploy.md)（首次部署）· [优化方案书-单游戏热更新.md](./优化方案书-单游戏热更新.md)（设计说明）

---

## 1. 怎么选发布方式

| 你改了什么 | 用什么 | 玩家感知 |
| --- | --- | --- |
| 单个（或同包）游戏规则 / 机器人 / 结算插件 | **单游戏热更新** | 仅该游戏维护；其它玩法与大厅照常 |
| 仅大厅 / 牌桌 UI（`apps/lobby-web`） | **`SCOPE=web`** | 无全站维护页；刷新或再进房拿新前端 |
| API / 账务 / 认证 / protocol / game-sdk / 多游戏一起改 | **全量更新 `SCOPE=full`** | 全站排水 → 维护页 → 结束后发补偿 |
| 只动房间服容器逻辑 | **`SCOPE=room`** | 会排水（与全量类似，但不强制重建 web） |
| 只动 API 容器 | **`SCOPE=api`** | 会排水 |

**原则**：能单游戏就不全站；能 `web` 就不重启房间服。

## 2. 单游戏热更新（推荐修 bug）

### 2.1 命令

```bash
cd /opt/1panel/apps/chess-and-cards

# 按 gameId
bash infra/1panel-game-update.sh dice

# 按包名（麻将五变体建议整包）
bash infra/1panel-game-update.sh @cc/game-cs-mahjong
```

常用 `gameId` 示例：`baccarat`、`blackjack`、`dice`、`niuniu`、`tuizhuanzi`、`doudizhu`、`texas`、`gomoku`、`xiangqi`、`cs-mahjong` 等。

### 2.2 脚本实际做什么

1. `git pull` 最新代码  
2. **变更范围门禁**：若改到 `packages/protocol`、`packages/game-sdk`、`packages/auth`、`apps/api-server` 或房间服核心文件 → **拒绝**，提示改走全量  
3. 对该游戏（同包连带）进入 **drain**  
4. 等待该游戏活跃真人对局清零  
5. **reload** 热加载插件 → **enable**  
6. **不会**调用全站 `/maintenance/*`，**不会**发全服补偿邮件  

### 2.3 前置条件

- `room-server` 已挂载 `./services/games`（见 `docker-compose.1panel.yml`）  
- `.env` 中有有效 `ADMIN_TOKEN`  
- 入口健康：`http://127.0.0.1:8090/health`（端口以 `.env` 的 `WEB_PORT` 为准）

### 2.4 GM 客户端操作（可不 SSH）

1. 打开根目录 `GM工具.bat` / `GM客户端.vbs`  
2. 填站点地址 + `ADMIN_TOKEN` 连接  
3. 左侧进入 **「单游戏热更运维」**  
4. 对目标行：**排水 →（等活跃真人桌=0）→ 热重载 → 启用**；紧急可先 **下架**  

同包多玩法（如麻将）会连带处理，面板有提示。

### 2.5 手动调 API（调试用）

鉴权：`Authorization: Bearer <ADMIN_TOKEN>`

```bash
API=http://127.0.0.1:8090
TOKEN='你的ADMIN_TOKEN'
GID=dice

# 列表
curl -s "$API/api/admin/games" -H "Authorization: Bearer $TOKEN"

# 排水 / 状态 / 热更 / 启用 / 下架
curl -s -X POST "$API/api/admin/games/$GID/drain"   -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' -d '{}'
curl -s       "$API/api/admin/games/$GID/status"  -H "Authorization: Bearer $TOKEN"
curl -s -X POST "$API/api/admin/games/$GID/reload"  -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' -d '{}'
curl -s -X POST "$API/api/admin/games/$GID/enable"  -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' -d '{}'
curl -s -X POST "$API/api/admin/games/$GID/disable" -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' -d '{}'
```

## 3. 按范围发布（SCOPE）

全量脚本：`infra/1panel-update.sh`

```bash
cd /opt/1panel/apps/chess-and-cards

# 默认：全站
bash infra/1panel-update.sh

# 只发前端（不排水、不补偿）
SCOPE=web bash infra/1panel-update.sh

# 只滚 API / 房间服（会排水 + 补偿逻辑与全量一致）
SCOPE=api bash infra/1panel-update.sh
SCOPE=room bash infra/1panel-update.sh
```

| SCOPE | 构建 | 排水 / 维护页 | 全服补偿 |
| --- | --- | --- | --- |
| `full` | 全部镜像 | 是 | 是 |
| `web` | 仅 web | **否** | **否** |
| `api` | runtime 相关 | 是 | 是 |
| `room` | runtime 相关 | 是 | 是 |

1Panel 计划任务示例（仅前端）：

```bash
SCOPE=web bash /opt/1panel/apps/chess-and-cards/infra/1panel-update.sh
```

## 4. 全站优雅更新（平台级）

适用于共享协议、账务、多游戏大改、首次部署后的常规大版本。

```bash
bash /opt/1panel/apps/chess-and-cards/infra/1panel-update.sh
# 等同 SCOPE=full
```

流程摘要：

1. 预构建镜像（旧服务仍对外）  
2. 全站 drain → 等所有真人对局结束 → updating 维护页  
3. 滚动重启后端 → 切换 web  
4. `maintenance/complete`：恢复服务 + 按版本幂等发补偿（默认 1,000 欢乐豆）  

首次部署与域名反代见 [1panel-deploy.md](./1panel-deploy.md)。

## 5. 日常巡检与排障

### 5.1 常用命令

```bash
cd /opt/1panel/apps/chess-and-cards

docker compose -f docker-compose.1panel.yml ps
docker compose -f docker-compose.1panel.yml logs -f --tail=100 api-server room-server web

# 健康（含单游戏不可用观测字段 gameOps）
curl -s http://127.0.0.1:8090/health | jq .

grep ADMIN_TOKEN .env

# 备份库
docker exec cc-postgres pg_dump -U cc chess_cards > backup_$(date +%F).sql
```

### 5.2 热更失败时

1. 看 `room-server` 日志中的 `热加载游戏包` / 报错  
2. 确认宿主机 `services/games/<包>/src/index.ts` 存在且卷已挂载  
3. 游戏可能停在 `disabled` + 失败文案 → 修好后再 `reload` / `enable`  
4. 若门禁拒绝：改走 `SCOPE=full` 全量更新  

### 5.3 排水一直等不完

- 查 GM 面板或 `.../status` 的 `activeHumanGames` / `activeRooms`  
- 可对异常房间在「房间实时透视」里强制流局重置或解散（谨慎）  
- 超时后脚本会退出并保持 `draining`，不会强行 reload  

### 5.4 本地冒烟（发版前）

```bash
# 全量规则冒烟
pnpm smoke:games

# 只跑某一款
# PowerShell:
$env:GAME_ID='dice'; pnpm smoke:games
# bash:
GAME_ID=dice pnpm smoke:games
```

## 6. 安全注意

- `.env` 含 `JWT_SECRET` / `INTERNAL_KEY` / `ADMIN_TOKEN`，勿提交仓库、勿群发  
- 生产必须 `NODE_ENV=production`，弱密钥会拒绝启动  
- 单游戏脚本**禁止**调用全站 maintenance 接口；不要手工对单游戏场景调 `maintenance/complete` 以免误发补偿  
- Postgres 与房间服端口保持内网，对外只反代 `8090`（或域名）
