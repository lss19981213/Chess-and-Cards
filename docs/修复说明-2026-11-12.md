## 二、P1 高危项（13/13 已修复）

**资金与公平性**

- **P1-1 断线/中止不扣钱**：`room.ts` 的 `removeSeat` 改为「先通知插件、再删座位」，插件能看到仍在座的离场者；`leave()` 去掉重复调用；人数不足中止本局时会调用 `releaseBets(roomId)` 退回已扣本金。
- **P1-2 余额静默截断**：`postgres.ts` 的 `credit` 移除 `greatest(...)`，改为 `balance + $2 >= 0` 条件更新，不足时抛 `InsufficientFundsError`；结算改为锁钱包行后按「实际可扣金额」入账，账本 `delta` 与 `balance_after` 始终自洽。
- **P1-3 打赏并发透支**：`/api/tip-dealer` 与 GM 扣款捕获 `InsufficientFundsError` 返回 400，不再出现 500。
- **P1-4 await 扣款后落进新局**：baccarat / dice / niuniu / blackjack / tuizhuanzi 在下注前记录 `roundNo`，扣款返回后复核 `roundNo + phase`，不符立即退款。
- **P1-5 游客接口无限制**：新增 `guestLimiter`（每 IP 10 分钟 3 个），并改用 `randomInt` 生成后缀。

**可用性**

- **P1-6 救济金永远领不到**：`buildTasks` 对 `kind === 'relief'` 直接以余额条件判定达成；领取时跳过进度校验。
- **P1-7 机器人行动未 await**：`actAsBot` 改为 `async` 并 `await handleIntent`，异常被捕获而不是打死进程。
- **P1-8 多端互踢**：`detach(playerId, socket)` 增加 socket 校验，旧连接的 close 不再清空新连接。
- **P1-9 房间泄漏**：`leave()` 统一调用 `checkEnoughPlayers()`，纯机器人房间和空房间正常回收。
- **P1-10 断线重连牌桌冻结**：`App.tsx` 收到 `RoomView` 时调用 `setRoomRef`，离开房间、房间解散时清空；收到 `ROOM_NOT_FOUND` 自动退回大厅。
- **P1-11 WS 无防护**：`maxPayload` 64KB、`verifyClient` 校验 Origin（默认同源，跨域需 `WS_ALLOWED_ORIGINS`）、监听地址改 `ROOM_HOST`（默认 127.0.0.1）、CORS 改同源回显；`maxPlayers` 做整数与范围校验。
- **P1-12 typecheck 跑不通**：根 `typecheck` 改为 `pnpm -r --if-present typecheck`，`build` 同步调整。实测 20 个包全部通过。

**安全**

- **P1-13 GM 口令**：改为只从 `Authorization: Bearer` 读取，`crypto.timingSafeEqual` 恒定时间比较，新增请求/失败双限流；`tools/gm-tool.ps1` 同步改为 header 鉴权，默认站点改为 HTTPS 占位符。另：账号不存在时执行 `burnPasswordCheck` 抹平响应时间差；5xx 不再回传内部错误信息。
- **P1-14 昵称冒名 / 头像**：`schema.ts` 增加 `lower(nickname)` 唯一索引（老库有重名时跳过创建但不阻断启动），两个仓储层都在更新时校验重名；头像改为校验真实体积（64KB）与文件头魔数。

## 五、验收步骤

```bash
pnpm install
pnpm typecheck          # 应全部通过
pnpm --filter @cc/lobby-web build
```

启动后按下面清单手动验证：

1. **验证码**：打开 `/api/captcha`，返回的 SVG 里搜不到 `text` 标签与明文字符，但页面能正常识别。
2. **密钥**：清空 `JWT_SECRET` 且 `NODE_ENV=production` 启动 api，应立即报错退出。
3. **限流**：伪造 `X-Forwarded-For` 连续请求 `/api/login`，仍按真实 IP 计数。
4. **重连**：进房间后断网 5 秒再恢复，牌桌应自动恢复而不是冻结。
5. **结算**：停掉 api 打一局，`services/room-server/.outbox/` 应出现 JSON；恢复 api 后 60 秒内文件消失、账本入账。
6. **排行榜**：把系统时间调到 0 点后观察只结算一次；重启服务不重复发奖。
7. **救济金**：余额低于 100 时可领取，高于 100 时按钮置灰。
8. **GM 工具**：新版 `GM工具.bat` 使用 Authorization 头，发放时带幂等键，双击不会重复发币。
